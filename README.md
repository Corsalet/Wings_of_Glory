# Wings of Glory

Аркадный сетевой воздушный бой на Three.js: советские самолёты от По-2 до Су-57, ракеты, тепловые ловушки и онлайн-режим 5 на 5 — до 10 реальных игроков в одном небе.

![Сетевой бой](docs/netbattle.png)

## Возможности

- **10 самолётов I–X ранга** — поршневая классика и современные реактивные (Су-35, Су-57 с подвижным вектором тяги)
- **Сетевой режим 5×5** — красные против синих, до 10 игроков; пустые слоты занимают боты
- **Профили и аккаунты** — уникальные никнеймы (дубликаты отклоняет сервер), регистрация и вход, прогресс и ангар хранятся на сервере и доступны с любого устройства
- **Вооружение и выживание** — пушки, самонаводящиеся ракеты, тепловые ловушки (уводят ракеты на дистанции больше 120 м), трёхступенчатое предупреждение о пуске (600 / 350 / 150 м)
- **Высший пилотаж** — манёвр «Кобра» (клавиша C), экономика, покупка и прокачка самолётов в ангаре

## Структура проекта

| Путь | Что это |
|------|---------|
| `download/wings_of_glory.html` | Игра — один самодостаточный HTML-файл (Three.js r128 с CDN) |
| `public/game.html` | Копия игры, которую раздаёт Next.js по `/` |
| `mini-services/wog-server/` | Мультиплеер-сервер: socket.io (`/wog/`), аккаунты, профили, SQLite (`data/wog.db`); сам же раздаёт клиент game.html |
| `mini-services/wog-server/Dockerfile` | Образ сервера одним сервисом (игра + мультиплеер на одном порту) |
| `render.yaml` · `railway.json` | Конфиги деплоя на Render (Blueprint) и Railway |
| `src/` | Next.js-хост: раздаёт игру как главную страницу, fallback-iframe |
| `worklog.md` | Журнал разработки: все задачи и изменения |

## Запуск локально

Нужен [Bun](https://bun.sh) (или Node.js 20+ для хоста).

```bash
# 1. Хост — Next.js, порт 3000
bun install
bun run dev

# 2. Мультиплеер-сервер — socket.io, порт 3030
cd mini-services/wog-server
bun install
bun run dev
```

Открыть `http://localhost:3000`. Игра без запущенного сервера доступна в одиночном режиме с ботами.

## Как устроена сетевая игра

Клиент подключается к серверу по WebSocket (`socket.io`, путь `/wog/`). Адрес сервера выбирается автоматически: `?srv=https://адрес` в ссылке → шлюз воркспейса → тот же origin, если страницу отдал сам игровой сервер. Сервер ведёт комнаты формата 5×5: распределяет игроков по командам, заполняет недостающие слоты ботами, синхронизирует позиции, стрельбу, ракеты и ловушки, начисляет награды и пишет прогресс в SQLite. Пароль и токен сессии хранятся только на сервере — поэтому один профиль можно открыть с любого устройства.

## Деплой мультиплеера (постоянная ссылка)

Сервер — один сервис: сам раздаёт игру и держит мультиплеер на одном порту. Есть два пути: **Next.js одним приложением** (мультиплеер встроен в Next-сервер) или **Docker-контейнер** с отдельным bun-сервером.

**TatNet / любой Next.js-хостинг (проще всего):** репозиторий — обычное Next.js-приложение, мультиплеер уже встроен в него. При открытии игры клиент сам «будит» встроенный сервер (`/api/wog` → socket.io на `/wog/`), отдельный сервис не нужен. Работает под Node ≥ 22.3 (`node:sqlite`) и под bun (`bun:sqlite`) — драйвер БД выбирается автоматически. Профили лежат в `./data/` относительно корня приложения (можно переопределить `WOG_DATA_DIR`).

**Render (бесплатно):** github.com → New + → Blueprint → выбери этот репозиторий — `render.yaml` подставит всё сам (собирает Docker-образ bun-сервера). Плюс: получишь адрес вида `https://wings-of-glory-xxxx.onrender.com` — это уже готовая ссылка на игру с мультиплеером. Минус: free-план засыпает после ~15 мин простоя (первый заход просыпается ~30–60 с), а БД игроков очищается при рестарте.

**Railway:** New Project → Deploy from GitHub repo → выбери репозиторий — `railway.json` укажет на Dockerfile. Аналогично получишь публичный адрес.

**GitHub Pages + внешний сервер:** статика Pages уже играет с сервером — добавь к ссылке игры параметр `?srv=https://адрес-твоего-сервера`, либо впиши адрес в `WOG_SRV_DEFAULT` внутри `wings_of_glory.html` (одна строка).

**Docker вручную:**
```bash
docker build -f mini-services/wog-server/Dockerfile -t wog-server .
docker run -p 8080:8080 -e PORT=8080 wog-server
```

Для чисто статической публикации (GitHub Pages без `?srv=`) достаточно файла `wings_of_glory.html` — одиночный режим с ботами работает без сервера.
